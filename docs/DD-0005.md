# DD-0005 — Collateral entry parser and schema (M2b)

**Traces to:** HLD-0002 §2 (entry format + schema), §3 (validation), §8 (errors),
§9 (DD split). Modules: `dod/collateral.py`, `dod/collateral_schema.py`.
Reuses DD-0001's `parse_block` with `fence="+++"` — one algorithm, two framings.

## §1 Entry format (normative)

A block begins at a line whose content is exactly `+++ <type>` and ends at the
next line whose content is exactly `+++`. Interior lines follow the DD-0001
subset (`key: value`, flow lists, `#` comments, blank lines). Everything
outside blocks is prose and is ignored; a file with zero blocks is valid.

```markdown
+++ role
id: code-reviewer
name: Code Reviewer
stage: 7
may_touch: [src/**, tests/**]
forbidden: [docs/specs/**]
traces: [REQ-0002]
+++
```

Why `+++` (HLD-0002 §1): it cannot be confused with `---` front matter or with
a `---` heading underline, so one file can hold both artifact front matter and
collateral blocks.

`<type>` must be one of the five known types — an unknown type is an error at
parse time, before schema validation (fail fast: a typo'd fence word would
otherwise look like a valid empty entry). Line numbers are carried so every
later message points at the opening fence (HLD-0002 §8).

## §3 Schema (normative)

**Bold = required.** Unknown keys are errors (HLD-0002 §2) — a misspelled
`may_touche` silently dropping a boundary is the failure this rule exists for.

| type | fields | constraints |
| --- | --- | --- |
| `role` | **id**, **name**, stage, produces, may_touch, forbidden, traces | stage ∈ 0..8; may_touch/produces are lists |
| `skill` | **id**, **name**, steps, traces | steps is a list |
| `gate` | **id**, **name**, **stage**, command, traces | stage ∈ 0..8; no `command` ⇒ human-run gate (AGENTS.md §5) |
| `message` | **id**, **name**, **channel**, **content**, audience, traces | channel ∈ `email`, `social`, `docs` |
| `asset` | **id**, **name**, **kind**, **rights**, license, traces | rights ∈ `original`, `licensed`, `cc-by-4.0` |

Common rules for every type:
- `id`: kebab-case `[a-z][a-z0-9-]*`, unique across **all** collateral files.
- `traces`: each value matches `^(REQ|UC)-\d{4}$` — format only; resolution is
  DD-0002's edge check (HLD-0002 §4).
- Error messages name the offending key and the allowed set, DD-0001 style:
  `collateral/roles.md:4: unknown field 'may_touche' (allowed: id, name, ...)`.

```python
def validate(entries: list[Entry]) -> list[CollateralError]:
    """Schema + cross-entry checks (id uniqueness). Returns ALL errors,
    never stops at the first (HLD-0002 §3)."""
```

Why all errors: collateral is authored in packs; an author fixing a directory
of entries wants the full list in one run, not one error per invocation.

## §5 Workspace integration

- `Workspace.load_collateral()` (DD-0001 §3) calls `parse_entries` per file,
  then `validate` over the union, and raises `CollateralError` prefixed with
  `path:line` — the CLI shows it verbatim (HLD-0002 §8).
- `Workspace.collateral` feeds `build(entries, collateral=...)` (DD-0002 §4),
  which turns `traces:` into `traces_to` edges.
- `dod validate` (DD-0004 §4) reports collateral errors in the same run.

## §6 Error handling

| Situation | Behavior |
| --- | --- |
| Unknown block type (`+++ widget`) | Error at the fence: `unknown entry type 'widget' (allowed: role, skill, gate, message, asset)` |
| Block opened, never closed | Error at EOF pointing at the opening fence: `block opened here is never closed` |
| Unknown key | Error naming the key and the allowed set |
| Missing required key | Error naming the key and the entry type |
| Duplicate id | Error at the second occurrence, naming the first file:line |
| Bad `traces` format | Error naming the value and the expected form |
| File with no blocks | Valid; contributes zero entries |

## §7 Testing strategy

- Parser: happy path; unknown type; unclosed block; comments and blank lines;
  `---` front matter and `+++` blocks coexisting in one file; exact line numbers.
- `parse_block` differential: DD-0001's suite re-run with `fence="+++"` — the
  shared algorithm must behave identically under both framings.
- Schema: each required key missing; unknown key; each enum constraint; id
  uniqueness across files.
- Golden: `examples/collateral/` validates clean; a broken-pack fixture yields
  the exact error list.

## §8 Open questions

- Should `rights: licensed` require a `license` value? Currently optional;

- Cap on `message.content` length? None pre-1.0.
