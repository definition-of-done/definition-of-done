# UC-0002 — Six months later, the app is still fixable

**Persona:** Vera again, or whoever inherits her app. **Job (JTBD-1, the "six months"
half):** change the software without fear, and know why anything exists.

## Context

The promise that separates Definition of Done from prototype tools is durability: every line
traces back to an approved intent (REQ-0001 §3). This use case is the product's core
"before/after" story and its most demoable moment.

## Scenarios

**S1 [happy] A change request goes through the chain, not the code.**
GIVEN a shipped app with an approved `UC-0001`, WHEN a change request arrives,
THEN the UC and spec are updated first, tests are regenerated from the spec, code is
regenerated from the tests (Golden Rule, AGENTS.md §4), and the diff cites the UC.

**S2 [happy] "Why does this exist?" is answerable.**
GIVEN an unfamiliar part of the app, WHEN the maintainer runs `dod trace` or reads the
living docs, THEN every module resolves through `code → DD → HLD → REQ` to a written intent, and
the docs describe current reality (Stage 8 keeps them honest).

**S3 [edge] Orphan code is flagged, not trusted.**
GIVEN code exists with no `// Trace: DD-xxxx §N` marker — pasted, hand-hacked, or
forgotten, WHEN `dod trace` runs, THEN the orphan is reported with its location and the
choice offered is "write the artifact" or "delete the code" — both cheap, per principle 1.

**S4 [failure] A doc that drifted from reality fails the build.**
GIVEN docs or changelog that no longer match shipped behavior, WHEN the release gate runs
(Stage 8: traceability fully resolves, docs updated in the same diff),
THEN the release fails until docs and code agree.

## Out of scope

Automatic reverse-engineering of intent from existing code (a future migration tool, not
v1); guaranteeing the *quality* of whatever intent was written down — that is the humans'.
