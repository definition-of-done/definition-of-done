## §1 Graph construction

```python
EDGE_TYPES: dict[str, tuple[str, str]] = {   # name -> (from_kind, to_kind)
    "uc_covers_req":   ("UC", "REQ"),    "spec_implements_uc": ("SPEC", "UC"),
    "hld_fulfills_req":("HLD", "REQ"),   "dd_details_hld":     ("DD", "HLD"),
    "dd_fulfills_req": ("DD", "REQ"),    "test_covers_uc":     ("CODE", "UC"),
    "test_covers_dd":  ("CODE", "DD"),   "code_implements_dd": ("CODE", "DD"),
    "role_serves_uc":  ("ROLE", "UC"),   "role_enforces_req":  ("ROLE", "REQ"),
    "entry_supports":  ("ENTRY", "REQ"), "entry_evidence":     ("ENTRY", "CODE"),
}

class TraceGraph:
    def build(self, ws: Workspace) -> None:
        """Nodes from DD-0001 loader; edges from fields (structured) and
        body text (prose). Deterministic: nodes sorted by id, edges by
        (type, from, to)."""

    def edges(self, *, type: str | None = None,
              frm: str | None = None, to: str | None = None) -> list[Edge]
    def reachable(self, node: str, *, direction: str,
                  types: set[str] | None = None) -> set[str]
    def orphans(self, kind: str) -> set[str]
```

Prose extraction (the `**Traces to:**` lines, free-text mentions): collect
`\b(REQ|UC|HLD|DD)-\d{4}\b` from the body, then **type each candidate by
kind-pair legality**: for an edge `X --name--> Y`, keep only candidates whose kind
matches `EDGE_TYPES[name]`. A UC body mentioning `REQ-0001` yields `uc_covers_req`;
the same mention of `UC-0002` from a UC body matches no UC-source edge and is
dropped silently (cross-references in prose are normal). Why legality-filtering
instead of section-parsing: prose is for humans; the checker's job is resolution,
not grammar policing (ARCH §4.2 "resolve, not suggest").

CODE nodes do not exist as artifacts: `test_covers_*` / `code_implements_dd` edges
come from `// Trace:` comments collected by a file walker injected at build time
(`trace_sources: Iterable[TraceSource]`), so M3 never imports M4's code scanner and
`dod trace` works without touching source files when those edges are not requested.

## §3 `dod trace` rendering

```python
def explain(graph: TraceGraph, node_id: str) -> str:
    """Human report: node summary, outgoing edges grouped by type, incoming
    edges likewise, then reachability roll-up ('reaches 2 UCs, 3 specs,
    12 tests'). Unknown id -> TraceNotFound listing the 3 closest ids
    (difflib.get_close_matches) -> CLI exit 2, rendered per HLD-0001 §9.3:
    `no node 'UC-0099' — no matching node in the graph. Check the id, or
    run 'dod trace' to see what the graph contains.`"""
```

`--format=json` emits `{"node": ..., "out": [...], "in": [...], "reaches": {...}}`
with keys sorted — stable across runs (HLD-0001 §9.2).

## §4 Error handling

| Condition | Behavior |
| --- | --- |
| Edge target missing from repo | edge kept, marked dangling; `check_trace` fails on it (TR001), `dod trace` prints it with `(missing)`. The finding names the file holding the edge, the missing target, and the fix: create the target or correct the reference (HLD-0001 §9.3) |
| Duplicate node id (two files, same `id:`) | build error → exit 1, both paths listed with the duplicated id and the choice: rename one id or delete one file (HLD-0001 §9.3) |
| Index sentinels unpaired | finding IX001 (FAIL): "docs/index.md: index block start without end marker — the index is broken"; next step: re-run with `--fix` (rewrites the region between begin and EOF) or restore the file from git (HLD-0001 §9.3) |
| Index absent | IX002 (WARN) only when `--fix` was requested or `dod check` runs with an existing index expected; plain check passes |
| Self-edge (X traces to X) | dropped at build; TR002 WARN naming the file and the self-referencing line, so the human can delete or correct the mention (HLD-0001 §9.3) |

Every message above follows HLD-0001 §9.3: a human seeing only the line knows
something is wrong, where it is, and what to do next.
