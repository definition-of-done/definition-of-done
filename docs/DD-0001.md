# DD-0001 — Front-matter parser and artifact model (M1, M2)

**Traces to:** HLD-0001 §2.1 (front-matter subset), §2.2 (Artifact), §8 (error handling).
Implements the parsing layer every other DD builds on. Modules:
`dod/frontmatter.py`, `dod/workspace.py`, `dod/artifacts.py`.

## §1 The front-matter subset

Grammar (repeated from HLD-0001 §2.1, normative here):

```
block   := "---" NL (line NL)* "---" NL?
line    := key ":" [space] value | comment("#...") | blank
key     := [A-Za-z][A-Za-z0-9_-]*
value   := scalar (optionally quoted) | flow-list "[" [scalar ("," scalar)*] "]"
```

```python
class FrontMatterError(ValueError):
    """Malformed block. .line holds the 1-based line number when known."""
    def __init__(self, message: str, line: int | None = None): ...

def parse_block(text: str, fence: str = "---") -> tuple[dict[str, str | list[str]], int]:
    """Parse a leading block delimited by `fence`. Return (fields, lines_consumed).
    Raise FrontMatterError on any violation."""

def parse(text: str) -> dict[str, str | list[str]]:
    """Convenience wrapper discarding the consumed-line count."""
```

Why hand-rolled (HLD-0001 §7): PyYAML accepts constructs we would have to reject
anyway, and its error messages point at parser internals, not user mistakes. Every
error message here follows HLD-0001 §9.3 — what happened, where/why (line and rule),
and what to do next: `line 3: unknown field 'owner' (allowed: id, req, ...) — remove
this line or rename it to an allowed field`.

**Decision (resolves ARCH §11 Q2): vendor a minimal Gherkin parser.** The feature
parser (M2a) is implemented in-house on top of this module — `parse_block` is
generalized with a `fence` parameter (above) so the collateral parser (DD-0005)
reuses the same algorithm with `+++` framing (HLD-0002 §1). Rejected: depending on
`gherkin-official` in the core — ARCH §8 fixes core dependencies at none, and a
zero-install core is the pre-1.0 adoption story (REQ-0001 §5). `gherkin-official`
stays a **dev-only** dependency: `scripts/check_specs.py` and the Stage-5 suite
differential-test our parser against it, so spec conformance is verified, not
assumed.

Algorithm (single pass over `text.splitlines(True)`):

1. Line 1 must be exactly `---` (trailing whitespace tolerated). Else
   `FrontMatterError("file must start with a '---' front-matter block — add a '---' "
   "metadata block at the top of the file", 1)`.
2. Scan until the closing `---`. Inside the block: blank lines and `#` comments
   skip; anything before `:` must match `key`; a key seen twice is an error.
3. Values: strip; empty → `""`. Leading `[` → list form: split on commas, strip
   items, drop empty items (`[]` → `[]`), each item unquoted. Otherwise scalar:
   if wrapped in matching `"` or `'`, strip one layer and unescape `\\`, `\n`,
   `\"`, `\'`; else take verbatim (no escape processing — plain scalars are
   literal, which is what artifact authors expect).
4. Missing closing `---` → `FrontMatterError("unterminated front-matter block — add "
   "the closing '---' line after the metadata")`.

Explicit non-goals (tested as rejections): nested mappings, block lists (`- item`),
anchors, multi-line scalars, tabs before keys.

```python
def render(fields: dict[str, str | list[str]]) -> str:
    """Inverse of parse for --fix writes. Keys in canonical order (§2.2),
    list values as flow style, scalars quoted only when they must be
    (leading/trailing space, leading '#', ': ' or ' #' inside, or a value
    that would parse as a list). Round-trip property tested:
    parse(render(f)) == f."""
```

## §2 Workspace

```python
class Workspace:
    def __init__(self, root: Path): ...   # no I/O

    @classmethod
    def discover(cls, start: Path) -> Workspace:
        """Walk up from `start` for docs/index.md. Raise WorkspaceNotFound
        (→ CLI exit 2, HLD-0001 §8) with the searched paths in the message."""

    @property
    def docs(self) -> Path: ...    # root/"docs"
    @property
    def specs(self) -> Path: ...   # root/"specs"

    def all_artifacts(self) -> list[Path]:
        """Sorted docs/*.md + specs/*.feature + roles/*/SKILL.md. Missing
        directories contribute nothing (a repo with only docs/ is valid)."""
```

Why `docs/index.md` is the root marker: it is the traceability root (ARCH §4.1), so
a tree without it is not a workspace — running `dod` in your home directory must
refuse, not scan 40k files.

## §3 Artifact model

```python
ID_KINDS: dict[str, re.Pattern] = {
    "REQ": re.compile(r"REQ-\d{4}$"), "UC": re.compile(r"UC-\d{4}$"),
    "HLD": re.compile(r"HLD-\d{4}$"), "DD": re.compile(r"DD-\d{4}$"),
}

class Artifact:
    path: Path            # relative to workspace root, POSIX separators
    id: str
    kind: str             # "REQ" | "UC" | "HLD" | "DD" | "SPEC" | "ROLE"
    fields: dict          # parsed front-matter
    body: str             # text after the block
    degraded: bool        # True → bold-header fallback (§4)

def load(path: Path, root: Path) -> Artifact:
    """Parse one file. Raise ArtifactError (message includes path) for:
    unreadable file, unknown ID kind, ID/filename mismatch, duplicate keys."""
```

ID derivation: markdown artifacts take their id from the `id:` field and must match
the filename stem (`docs/REQ-0001.md` ↔ `REQ-0001`) — mismatch is an error, because
trace edges are written as free text elsewhere and the filename is what humans grep.
Specs derive `kind=SPEC`, `id=UC-0001` from `specs/UC-0001.feature`; specs carry no
front-matter. Roles derive `kind=ROLE`, `id=<directory name>` from `roles/<id>/SKILL.md`.

## §4 Legacy bold-header fallback

Some pre-template artifacts (this repo's own Stage 0–3 files) carry
`**Traces to:** REQ-0001` instead of front-matter. Rule (HLD-0001 §8): if the file
lacks a front-matter block, scan the first 40 lines for
`^\*\*(?:Traces to|Covers|Requirement|Spec|Design|Tests|Source):\*\*\s*(.+)`
and extract `\b(?:REQ|UC|HLD|DD)-\d{4}\b` matches as the reference set.

```python
def degraded_fields(text: str) -> dict | None:
    """Fields synthesized from bold headers, or None if nothing matched.
    `id` always comes from the filename stem. Returns degraded=True marker
    via Artifact.degraded; check_* emits one WARN per degraded artifact
    (never a FAIL) naming the missing fields and recommending
    'dod check --fix' (HLD-0001 §9.3)."""
```

Why WARN not FAIL: dogfooding is a launch requirement (REQ-0001 §3) and the repo's
own history predates the templates; `dod check --fix` rewrites these files with real
front-matter, and the WARN disappears. A hard FAIL would make the first run of the
tool on its own repo red — a bad first impression that teaches users to disable checks.

## §5 `--fix` rewriting

`dod check --fix` may rewrite front-matter only, never bodies. Implementation:
`load()` keeps `(fields, consumed_lines, body)`; fix handlers mutate `fields`;
`render(fields) + body` is written back with the original encoding and LF endings.
Files that were `degraded` gain a synthesized block; their bold-header lines stay in
the body (documentation, not structure). Property test: fixing an already-clean file
is byte-identical (idempotence, HLD-0001 §8).

## §6 Error handling summary

| Condition | Behavior |
| --- | --- |
| No workspace root | `WorkspaceNotFound` → exit 2, hint `dod init` |
| Malformed block | `FrontMatterError` → finding `FM001` at file level, exit 1 |
| Unknown field | finding `FM002` (WARN) — forward compat with template v2 |
| ID/filename mismatch | `ArtifactError` → finding `AR001`, exit 1 |
| Unreadable file | finding `AR002` (permission/encoding), exit 1 |
| No bold headers, no block | treated as content file: skipped, no finding |

Every message above follows the message content standard (HLD-0001 §9.3): what
happened, where/why (path:line + rule id + offending content), what to do next.
`WorkspaceNotFound` is the one message rendered directly by the CLI (DD-0004 §6).
