# DD-0003 — Gate framework and substrate checks (M4)

**Traces to:** HLD-0001 §5 (Check protocol, registry, inventory), §8 (error handling).
Modules: `dod/gates/__init__.py` (framework), `dod/gates/checks.py` (substrate
checks), `dod/codescan.py`. Collateral checks live in DD-0005/6/7 and register
through this framework.

## §1 Protocol and registry

```python
SEVERITY_RANK = {"WARN": 0, "FAIL": 1}

@dataclass(frozen=True)
class Finding:
    check: str; severity: str; path: str; line: int | None
    message: str; fixable: bool = False

@dataclass(frozen=True)
class CheckResult:
    check_id: str; stage: int | None; findings: tuple[Finding, ...]
    @property def ok(self) -> bool: ...       # no FAIL findings

class Check(Protocol):
    id: str; severity: str; stage: int | None
    def run(self, ctx: GateContext) -> CheckResult: ...

class GateContext:                       # built once per `dod check` run
    ws: Workspace; graph: TraceGraph; specs: dict[str, SpecFile]
    code: CodeIndex; collateral: CollateralStore
    options: RunOptions                  # --stage, --fix, --only, --json

_REGISTRY: list[Check] = []
def register(check: Check) -> None: ...  # import-time; duplicate id = crash
def registry() -> tuple[Check, ...]: ... # sorted by id, deterministic
```

Why import-time registration with a hard crash on duplicates: check ids are public
surface (HLD-0001 §5); a silent collision would make CI results depend on import
order. The crash happens in dev the first time someone adds a bad check.

`run_all(ctx) -> list[CheckResult]`: filters by `--stage` (a check runs when
`check.stage is None or check.stage == ctx.options.stage`), executes in registry
order, catches every exception from `run()` and converts it to
`Finding(check=..., severity="FAIL", message=f"check crashed: {exc!r}")` — a
crashed check fails the run (HLD-0001 §8) but never aborts the other checks.

## §2 Code index (the `// Trace:` scanner)

```python
TRACE_RE = re.compile(r"(?://|#|<!--|/?\*)\s*Trace:\s*([A-Z]+-\d{4}(?:,\s*[A-Z]+-\d{4})*)")

class CodeIndex:
    @classmethod
    def scan(cls, root: Path, include=("*.py", "*.ts", "*.js")) -> CodeIndex
    traces: dict[str, list[tuple[Path, int]]]   # id -> [(file, line)]
    def files(self) -> Iterable[Path]
```

Line comments only (first token of the comment), one pass, files > 1 MiB skipped
with a WARN (generated bundles are not hand-traced). The scanner is injected into
`TraceGraph.build` as `trace_sources` (DD-0002 §1). Why regex not AST: Trace
comments must work in any language (REQ-0001 §2.3 harness-agnosticism), and the
comment form is identical in the languages we ship examples for.

## §3 Substrate checks

All operate on `ctx`; each is a class in `checks.py`, id per HLD-0001 §5.1.

**`check_frontmatter` (FM0xx, WARN-capable)** — every artifact from
`ws.all_artifacts()` loads without `FrontMatterError`; degraded artifacts (DD-0001
§4) emit one WARN each naming the file and the fix command.

**`check_ids` (ID001, stage 0–4)** — per-kind uniqueness (loader already errors on
collision; this surfaces it as findings), filename↔id match, zero-padded format.

**`check_uc_coverage` (COV001, stage 2)** — FAIL per REQ with no incoming
`uc_covers_req`; FAIL per UC with no outgoing one. Message names the exact missing
edge: `"REQ-0002 has no UC covering it (add a UC whose front-matter lists req: REQ-0002)"`.

**`check_spec_coverage` (COV002, stage 3)** — FAIL per UC without a
`specs/UC-xxxx.feature`; parse each spec with `gherkin_official.parser.parse(text)`
— `ParseError` becomes FAIL `COV003` with gherkin's line/message verbatim (it is
already good). Empty feature (no rules) → FAIL.

**`check_design_coverage` (COV004, stage 4)** — FAIL per REQ with no incoming
`hld_fulfills_req`; FAIL per HLD with no incoming `dd_details_hld`. This is the
Stage-4 mechanical gate from ARCH §5.

**`check_trace` (TR001/2, all stages)** — dangling edges (target id referenced but
no node), self-edges. Dangling is FAIL: a trace that resolves to nothing is a lie
(ARCH §4.2).

**`check_orphans` (ORP001, WARN)** — nodes with zero edges of any type, excluding
`docs/index.md` and REQ-0001-adjacent meta files listed in `.dodignore`.

**`check_index` (IX001/2/3, stage 8)** — sentinels paired; table content equals
`render_table(graph)` byte-for-byte (drift → FAIL with `--fix` available); every
id in the table exists.

**`check_trace_comments` (TC001, stage 6, WARN)** — public functions/classes in
scanned code with no `Trace:` comment within 3 lines above the def. WARN at first
(legacy code), planned FAIL once the repo is migrated — the severity lives in one
constant so the flip is a one-line, spec-tracked change.

**`check_role_manifest` (RL001, stage 1)** — parse `roles/*/SKILL.md` per
HLD-0001 §6: required keys present, `dod:` block keys exactly the allowed set,
`stage` in 0–8, `may_touch`/`forbidden` are lists, glob syntax compiles with
`fnmatch.translate`.

## §4 `--fix` integration

Fixable findings: IX003 (rewrite table), degraded front-matter (synthesize block),
missing index (create). Mechanics in DD-0001 §5. `--fix` never touches findings
whose fix would change semantics (coverage gaps, dangling edges) — the tool cannot
invent intent, only formatting (AGENTS §8.2 applies to us too).

## §5 Error handling

| Condition | Behavior |
| --- | --- |
| Check raises | FAIL finding `check crashed: ...`, run continues (§1) |
| `gherkin_official` import fails | impossible post-install (hard dep); guarded by one unit test pinning the API call shape |
| `.dodignore` unreadable | WARN, treated as empty |
| Code dir missing (e.g. no `src/`) | CodeIndex empty; TC001 and code edges silently absent (repo may legitimately be docs-only at Stage 4) |

## §6 Test hooks (Stage 5)

- Registry: duplicate-id crash, sorted determinism, `--stage` filtering.
- Each check: pass fixture + one minimal failing fixture per finding code
  (COV001…IX003), asserting exact ids/severities — these are the public contract.
- Crash isolation: a stub check that raises does not stop its neighbors.
- codescan: comment forms per language, 1 MiB skip, multiple ids per comment.
Spec anchors: UC-0001 (gate pass/fail), UC-0002 (trace checks), UC-0003 (CI
exit-code semantics).
