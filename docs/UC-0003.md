# UC-0003 — Approve the work, don't redo it

**Persona:** Priya, seasoned software engineer. **Job (JTBD-2):** "Make agents produce
software to engineering standards — specified, tested, traceable — so I can approve work
instead of redoing it."

## Context

Priya does not trust agent output and has opted out of the productivity. Her cost model:
reviewing code she never asked for costs more than writing it herself. The product must
invert that — gates decide what merges, the diff is explainable, and her review time buys
confidence, not rework (REQ-0001 §3).

## Scenarios

**S1 [happy] Contracts first, agents after.**
GIVEN Priya has approved the HLD/DD for a module, WHEN she hands a task to an implementer
agent, THEN tests are generated from the Gherkin spec and fail for the right reason before
any implementation exists (Stage 5), and the implementing agent may write only inside its
declared module scope (role `write:` scope, AGENTS.md §6).

**S2 [happy] Green is not enough.**
GIVEN an agent's branch passes the full suite, WHEN a merge is attempted, THEN the Stage 7
gate mechanically refuses until review notes exist that predate the merge, and the judgment
inside those notes — Review Agent verdict plus Priya's signoff — blocks the merge for
unreadable names, missing "why" comments, or drive-by refactors (AGENTS.md §7: messy-but-
green is not done; ARCH-0001 §5: the gate checks the notes exist, the Review Agent and
human decide what they say).

**S3 [edge] The agent tries to move the goalposts.**
GIVEN a failing test, WHEN an agent marks it skipped or xfail, THEN the Stage 6 gate fails
its no-skipped/xfail check; WHEN it instead edits the spec or test to match its code, THEN
that write lands outside the Implementer's declared scope — roles may not touch tests or
specs (AGENTS.md §6) — and is flagged as a containment violation. The prohibition is
mechanical, not a plea.

**S4 [failure] Priya can explain the diff out loud.**
GIVEN a PR reaches her review, WHEN she reads it, THEN every public code unit cites a
`DD-xxxx §N` section she approved, and anything that does not cite is already flagged by
`dod trace` as an orphan — her audit is a check, not an excavation.

## Out of scope

Replacing Priya's architectural judgment (agents propose, she disposes); code review of
non-`dod` repos; enforcing her team's style beyond the clean-code checklist.
